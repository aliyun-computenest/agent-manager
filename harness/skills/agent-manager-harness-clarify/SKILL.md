# Harness Stage: Clarify

1. Confirm the design and UI inputs, real user path, in-scope behavior, explicit
   exclusions, success criteria, and required live integrations.
2. Identify missing platform-owned inputs such as acceptance command, target
   environment, credentials reference, or required approval.
3. Use `harness ask` when any missing choice would materially change the work.
4. Do not design a speculative implementation or start downstream work while a
   required answer is missing.

Complete only when the inputs are actionable. Evidence should summarize the
agreed scope, success criteria, constraints, and any recorded human decision.
